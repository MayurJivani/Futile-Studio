# Postcards

The desk at `/post`, the owner's `/mailbox` and the public `/track` page.

## One card, drawn one way

`src/components/Postcard.astro` is the only card markup and `paint()` in `src/lib/postcard.js` the only code that fills it. The desk paints the draft, the other two paint the stored row, so a card looks as it was sent. Sizes are container units, so it scales like a picture. Long messages get smaller writing rather than being cut off.

The flip bug: Motion leaves an inline `transform` on what it animates, and on `.card` that beat `.is-back`, so after Surprise me or Return to sender the card never turned again. The wiggle now runs on a holder element.

## The journey

`src/data/postal.js` computes the whole route from what was stored at posting: id, time, country (`CF-IPCountry`) and direction. There is no cron and no status column; "where is it" is a pure function of now, shared by the server and the pages.

- Germany: 2 days. Abroad: 3 days, plus one per 4000 km, plus up to a day of luck, capped at 7.
- Legs: evening collection, outward mail centre, gateway, flight (truck under 1200 km), Frankfurt, customs from outside the EU, inward mail centre, morning round. No Sunday delivery.
- Local time is the longitude's solar offset. No time zone database, which is plenty for scan times.
- No usable country (Tor, none sent): the card is "origin not recorded", 3 days, and draws no international leg.

## Access

- Receipt numbers are sequential, so they open nothing. `/track` takes a random 96-bit code from the receipt. It never returns the reply address or visitor name.
- Sent links are also kept in the visitor's browser, listed on the desk. There are no accounts, so losing the link loses the card.
- `/api/mailbox` stays behind Cloudflare Access. Replying also needs an `X-Futile-Post` header: a form post is a simple request a foreign page could send with the owner's Access cookie, and the custom header forces a preflight CORS refuses.

## Futile Mail

The owner writes back from `/mailbox`, to delivered cards only. A reply is a row with `direction = 'out'` and `parent` set, and travels Paderborn to the sender's country. The sender sees it on their own tracking page. Its writing and photo stay out of the API response until delivery.

## Photos

Sniffed from the bytes, JPEG, PNG or WebP only, 4 MB cap. No image library is installed, so `server/lib/images.js` removes metadata by walking the file structure: EXIF, XMP, comments and text chunks go, and a JPEG keeps only its orientation. Anything that does not parse is refused. It does not decode pixels, so an image with valid structure and broken data still passes. Adding `sharp` and re-encoding would close that. Files live in `STUDIO_UPLOAD_DIR/postcards` under random names, are served from `/api/postcards/photos` (Caddy only proxies `/api` and `/ws`, so `/media` never reaches the API in production) and are checked only after the card itself passes, so refused cards never reach the disk.

## Data

`makePostcards()` adds missing columns on boot and gives old cards a tracking code; running it twice changes nothing. `src/data/geo.js` is generated by `scripts/postal-geo.mjs`.

Checks: `node server/lib/postcards.selfcheck.js`, `node server/lib/images.selfcheck.js`, `node src/data/postal.selfcheck.js`.
